# 세탁 프롬프트 개선

## 순서
1. 바꾸기 전에 `npm run eval`을 실행해 기준 수치를 기록한다 (`docs/eval-history.md`에 자동 추가).
2. 고칠 프롬프트를 정한다: `apps/api/src/prompts/`의 판정(judge), 요약(summary), 부분 세탁(ask).
3. 한 번에 한 가지만 바꾼다 (예: 예시 추가, 출력 스키마 설명 강화, 금지 표현 추가).
4. fairness.md를 지키는지 확인한다: 단정 표현 금지, `evidence`·`quote`는 원문 그대로, 리뷰에 없는 사실 금지.
5. 프롬프트를 저장하면 eval-on-save hook이 품질 검사를 다시 돌린다. 결과를 1번과 비교한다.
6. 수치가 나빠졌으면 되돌린다. 좋아졌으면 커밋 메시지에 전후 수치를 적는다 (`feat(wash-pipeline): 판정 프롬프트 예시 추가, 확실한 얼룩 정밀도 82→91%`).
7. docs/KIRO.md의 "Kiro가 바꾼 결정" 표에 한 줄 추가한다.

## 하지 않는 것
- 평가 데이터(`scripts/eval/data/`)를 보고 그 리뷰에만 맞춘 예시를 프롬프트에 넣지 않는다.
- 숫자 계산을 프롬프트에 맡기지 않는다.
