# 제품: 별점세탁소

쿠팡 상품 리뷰에서 체험단, 제품 제공 같은 대가성 리뷰(얼룩)를 걷어내고, 세탁 후 평점과 얼룩을 뺀 리뷰로만 만든 세탁 후 요약을 보여주는 크롬 확장 프로그램이다. 카카오맵은 쿠팡이 완성된 뒤 추가한다.
Kirothon 2026 출품작이며 주제는 "내 일상에 바로 적용할 수 있는 서비스"다. 팀 규랑이 탐험대(재현, 규리, 주영, 정민).
쿠팡, 카카오와 제휴하지 않은 비공식 도구다.

## 사용자
- 쿠팡에서 리뷰와 별점을 보고 물건을 사는 사람
- (다음 단계) 카카오맵 후기로 음식점과 카페를 고르는 사람
- 공통 고민: 별점이 대가성 리뷰로 부풀려져 있고, 궁금한 것 하나를 찾으려고 리뷰 수백 개를 스크롤해야 한다

## 지원 사이트
- 1차 목표는 쿠팡이다. 카카오맵은 쿠팡의 평가자 체험 시나리오가 모두 동작한 뒤에만 시작한다.
| 사이트 | 페이지 | 🔴 확실한 얼룩 신호 | 🟡 의심 얼룩 신호 |
|---|---|---|---|
| 쿠팡 | 상품 상세 | 쿠팡 체험단 표시, "제공받아" 등 대가성 문구 | 구체성 없는 극찬 |
| 카카오맵 (다음 단계) | 장소 상세 | "리뷰 이벤트로 받은", "리뷰 약속" 등 명시 | "서비스 감사해요" + 5점, 짧은 극찬 |

- 특정 기간에 몰린 별점 같은 시점 패턴은 신호로 쓰지 않는다. 너무 불확실하다.
- 네이버 지도는 로드맵이다. MVP에서 만들지 않는다.

## 세탁소 용어 (코드, UI, 문서에서 이 용어를 일관되게 쓴다)
| 용어 | 의미 | 코드 식별자 |
|---|---|---|
| 세탁 요청 | 사용자가 입력하는 자연어 질문 | `request` |
| 얼룩 | 대가성 리뷰 | `stain` |
| 확실한 얼룩 🔴 | 플랫폼 체험단 표시, 원문에 대가성이 명시된 리뷰 | `stain: "certain"` |
| 의심 얼룩 🟡 | 명시는 없지만 대가성 신호가 있는 리뷰 | `stain: "suspected"` |
| 깨끗한 리뷰 | 얼룩이 아닌 리뷰 | `stain: "none"` |
| 얼룩 신호 | 판정 이유의 종류 | `signal` |
| 근거 문장 | 판정 근거가 된 원문 문장 | `evidence` |
| 세탁 전 / 세탁 후 평점 | 불러온 리뷰 전체의 평균 / 얼룩을 제외한 평균 | `before` / `after` |
| 부분 세탁 | 특정 주제 리뷰만 골라 보기 | `topics` |
| 세탁 코스 | 해석된 세탁 요청 | `course` |
| 세탁 후 요약 | 얼룩을 뺀 리뷰로만 LLM이 쓴 2~3문장 요약. 문장마다 근거 리뷰 ID | `receipt.summary` |
| 세탁 영수증 | 결과 카드 (기준 리뷰 수, 얼룩 수, 평점, 세탁 후 요약, 장점·단점) | `receipt` |
| 세탁 태그 | 페이지의 각 리뷰 옆에 붙는 판정 배지 | `tags` |
| 입고 | 페이지에서 리뷰를 추출하는 단계 | `intake`, 입고 어댑터 |

## 세탁 코스
| 코스 | 평점에서 빼는 것 | 결과 |
|---|---|---|
| 표준 코스 | 🔴 확실한 얼룩 | 세탁 후 평점, 세탁 후 요약, 장점/단점. 🟡는 태그만 붙인다 |
| 부분 세탁 | 표준과 같음 | 주제(무게, 발열, 사이즈 등) 관련 리뷰 하이라이트와 그 주제에 대한 세탁 후 요약 |
| 이벤트 얼룩 제거 (다음 단계) | 🔴 중 리뷰이벤트 | 카카오맵에서 서비스를 받고 쓴 리뷰를 뺀 요약 |
| 섬세 코스 | 🔴 + 🟡 | 의심 얼룩도 평점에서 빼고, 리뷰마다 근거 문장 표시 |

- 🟡 의심 얼룩은 모든 코스에서 판정하고 태그를 붙인다. 평점에서 빼는 건 섬세 코스뿐이다.
- 세탁 후 요약은 모든 코스에서 만든다. 요약의 재료는 그 코스에서 평점에 포함된 리뷰(`include: true`)뿐이다.

## 세탁 원칙
1. AI는 판정만, 숫자는 코드가 계산한다. 평점과 개수를 LLM에게 계산시키지 않는다.
2. 근거 없는 요약은 없다. 요약 문장마다 근거 리뷰 ID가 있어야 한다.
3. 정직하게 표시한다. "최근 리뷰 N개 기준"을 밝히고, 의심 얼룩은 단정하지 않고 신호와 근거로만 보여준다.
4. 세탁 전 평점은 페이지에 표시된 평점이 아니라 불러온 리뷰로 계산한다. 페이지 평점은 참고용으로 같이 보여줄 수 있다.

## 평가자 체험 시나리오 (MVP의 기준)
1차 심사는 발표 없이 평가자가 레포와 확장을 직접 써 보고 평가한다. 아래가 README 안내만으로 끊김 없이 동작해야 한다.
1. Releases의 zip을 받아 크롬에 압축해제 확장으로 로드한다.
2. 쿠팡 상품 페이지에서 툴바의 🧺 아이콘으로 사이드 패널을 연다.
3. "체험단 리뷰 빼고 평점이랑 요약해줘" → 리뷰 최대 100개 입고, 세탁 전 → 세탁 후 평점, 세탁 후 요약, 리뷰에 🔴🟡 태그.
4. "무게 관련 리뷰만 보여줘" → 무게 관련 리뷰 하이라이트와 무게 요약. 요약 문장을 누르면 근거 리뷰로 스크롤.
5. "티 안 나는 광고 리뷰도 빼줘" → 섬세 코스로 의심 얼룩까지 뺀 평점과 요약.
6. (다음 단계) 카카오맵 음식점 페이지에서 "리뷰이벤트 빼고 맛 평가만 알려줘".

- 수치는 실제 페이지에서 코드가 계산한 값이다. README의 4.8 → 4.3은 예시다.
- 실패해도 화면이 멈추지 않아야 한다: 입고 실패, API 오류, 시간 초과 때마다 사이드 패널에 이유와 다음 행동을 보여준다.
