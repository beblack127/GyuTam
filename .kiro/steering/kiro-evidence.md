# Kiro 활용 기록 규칙

채팅에서 `#kiro-evidence`로 불러 `docs/KIRO.md`를 갱신할 때 쓴다.

- 실제로 한 일과 실제 숫자만 적는다. 계획은 "계획" 칸에만 둔다.
- 숫자는 레포에서 다시 셀 수 있어야 한다: tasks 체크박스 수(`tasks.md`), hook 실행 기록(`docs/eval-history.md`), 커밋 수(`git log --grep`), 이슈·PR 링크.
- 항목마다 "파일 / 무엇을 했나 / 결과 / 왜 이렇게 썼나"를 채운다.
- Kiro가 잡아낸 문제(hook이 막은 비밀키, 품질 검사가 잡은 정확도 하락, spec 검토에서 바뀐 설계)는 "Kiro가 바꾼 결정" 표에 날짜와 커밋으로 남긴다.
- 쓰지 않은 기능을 쓴 것처럼 적지 않는다. 비어 있는 폴더는 마감 전에 지운다.
