# 공정성·법적 기준 (반드시 지킬 것)

## 표현
- "가짜 리뷰", "조작", "사기" 같은 단정 표현을 UI 문구, LLM 프롬프트, 응답 어디에도 쓰지 않는다.
- 판정은 "대가성 가능성"으로 표현하고, 신호(`signal`)와 근거 문장(`evidence`)을 함께 보여준다.
- 🟡 의심 얼룩은 추정이라는 점을 UI에서 구분해 표시한다 ("의심" 수준의 문구).
- 영수증에는 항상 기준 리뷰 수(`basedOn`)를 표시한다.
- 쿠팡, 카카오와 제휴하지 않은 비공식 도구임을 README와 확장 설명에 밝힌다. 두 회사의 로고를 쓰지 않는다.

## 판정 근거
- `certain`은 두 경우에만 인정한다: 규칙(플랫폼 체험단 표시, 대가성 명시 문구)이 찾은 경우, LLM이 원문에 실제로 있는 대가성 문장을 `evidence`로 댄 경우.
- LLM이 추정만으로 낸 판정은 `suspected`까지만 허용한다.
- `evidence`는 원문 리뷰에 실제로 있는 문장이어야 한다. 코드로 원문 포함 여부를 확인하고, 없으면 판정을 한 단계 낮춘다 (`certain` → `suspected`, `suspected` → `none`).
- 플랫폼 배지처럼 문장이 없는 근거는 `evidence: null`로 둔다.
- 시점 패턴(특정 기간에 몰린 별점)은 신호로 쓰지 않는다.

## 요약 근거
- 요약의 모든 항목(`pros`, `cons`, 주제 요약)은 실제 입력 리뷰의 ID(`reviewIds`)를 하나 이상 가진다.
- LLM 응답에 입력에 없는 리뷰 ID가 있으면 버린다. 근거가 없는 요약 항목은 표시하지 않는다.
- 세탁 후 요약(`summary`)은 얼룩을 뺀 리뷰(`include: true`)만 근거로 쓴다. 얼룩 리뷰를 근거로 댄 문장은 버린다.
- 요약에 리뷰에 없는 사실(스펙, 가격, 비교 상품)을 넣지 않는다. 프롬프트에 이 규칙을 적는다.

## 데이터 수집
- 서버에서 크롤링하지 않는다. 사용자가 보고 있는 페이지에서, 사용자가 세탁 버튼을 눌렀을 때만 리뷰를 읽는다.
- 리뷰는 최대 100개, 추가 요청은 1초 이상 간격. 쿠팡은 최대 10페이지(페이지당 10개). 실패하면 화면에 보이는 리뷰만 분석한다.
- 리뷰를 서버나 스토리지에 저장하지 않는다. 세탁이 끝나면 폐기한다. 로그에도 리뷰 원문을 남기지 않는다.

## 평가 데이터와 공개 자료
- 실제 리뷰 원문은 레포에 올리지 않는다. 평가용 원문과 어댑터 테스트용 HTML 스냅샷은 `scripts/eval/data/`에만 두고 git에서 제외한다.
- 단위 테스트용 리뷰는 AI로 만든 가상 리뷰(`packages/core/__fixtures__`)만 쓴다. 실존 업체, 인물을 등장시키지 않는다.
- 스크린샷, GIF, 발표 자료에서는 리뷰 작성자 이름을 가린다.

## 근거 법령
- 공정거래위원회 「추천·보증 등에 관한 표시·광고 심사지침」: 대가성 리뷰는 그 사실을 밝혀야 한다.
