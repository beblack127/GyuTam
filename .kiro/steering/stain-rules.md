# 얼룩 판정 기준

## 🔴 확실한 얼룩: 규칙 (재현, `packages/core/src/rules`)
코드가 찾는다. LLM 판정보다 우선한다.

| `signal` | 찾는 것 | 예시 |
|---|---|---|
| `platform_badge` | 쿠팡이 붙인 체험단 표시 (`badges` 또는 본문의 쿠팡 고정 문구) | "쿠팡체험단", 체험단 고지 문구 (정확한 문구는 intake.md 확인 결과) |
| `disclosure` | 대가성 명시 | "체험단", "제공받아", "제공 받아", "협찬", "원고료", "소정의", "무상으로 제공", "무료로 제공", "업체로부터", "지원받아" |
| `review_event` | 판매자 리뷰 이벤트 명시 | "리뷰 이벤트", "리뷰이벤트", "포토리뷰 이벤트", "리뷰 작성 시", "리뷰 쓰면", "사은품 받", "적립금 받" |

**부정 문장은 얼룩이 아니다.** 문구 앞뒤 15자 안에 부정 표현이 있으면 그 문구는 무시한다.
- 부정 표현: "아니", "아님", "아닙", "않", "안 받", "없이", "내돈내산", "내 돈 내 산", "직접 구매", "제 돈으로"
- 예: "제공받은 거 아니고 내돈내산입니다" → 얼룩 아님. "체험단 아닙니다" → 얼룩 아님.
- `evidence`에는 걸린 문구가 들어간 원문 문장을 그대로 넣는다. `platform_badge`가 배지에서 왔으면 `evidence: null`.
- 띄어쓰기 차이는 무시하고 찾는다 ("제공 받아" = "제공받아").

## 🟡 의심 얼룩: LLM (주영, `apps/api/src/prompts/judge`)
규칙에 걸리지 않은 리뷰만 LLM에 보낸다. 아래 기준 중 하나 이상에 해당하고, 그 근거 문장을 원문에서 그대로 인용할 수 있을 때만 `suspected`.

| 기준 | 설명 | 예시 |
|---|---|---|
| 경험 없는 칭찬 | 사용 상황, 기간, 구체적인 장단점 없이 칭찬만 있다 | "최고예요 강추합니다!! 완전 만족!!" |
| 홍보 문구 반복 | 상품명, 상품 설명의 홍보 문구를 그대로 반복한다 | "초고속 PD 충전에 슬림한 디자인까지 갖춘 프리미엄 보조배터리" |
| 외부 유도 | 구매 링크, 할인 코드, 블로그·SNS·다른 채널 언급 | "자세한 후기는 블로그에", "할인코드 XX" |
| 판매자 말투 | 판매자나 홍보 담당자처럼 쓴 문장 | "고객님들께 자신 있게 추천드립니다" |

- 기준에 애매하게 걸치면 `none`으로 둔다. 의심 얼룩은 적게, 확실하게.
- LLM은 `certain`을 낼 수 있지만, 원문에 대가성 문장이 있을 때만이다. 코드가 확인하고 아니면 `suspected`로 낮춘다.
- 별점만 보고 판단하지 않는다. 5점이라는 이유로 의심하지 않는다.
- 프롬프트와 출력에 "가짜", "조작", "사기"를 쓰지 않는다 (fairness.md).
